### B. Bugs / suspicious code in the rewrite files read

1. **`src/hooks/use-session.ts:79-88` — no zero-organization path.** A user with no organizations gets `organization === undefined` and is dropped straight into the tabs. The old app routes to `/create-organization`. No screen exists to recover.
2. **`src/hooks/use-session.ts:47` — session silently half-dead when the email claim is unreadable.** `signedIn` requires `!!email`; `rest-auth.ts:126 emailFromIdToken` returns `null` on any parse failure and a restored session has no other email source, so `queries.user.list` never enables → `uid` stays null → `use-membership-sync` never runs → every role check reads viewer. No error is shown.
3. **`src/hooks/use-session.ts` — user/org query errors are discarded.** Neither `isError` is read; a failed org fetch presents as "you have no organizations". Directly against the "never present unknown as normal" rule (§6b item 2).
4. **`src/hooks/use-membership-sync.ts:41` — stale role retained.** `if (!member) return;` means a user removed from the organization keeps the previously cached `memberType`/`memberId` instead of dropping to null.
5. **`src/app/menu.tsx:66-72` — organization list has no loading/error/empty state and no pagination.** A failed request renders an empty card under the "Organizations" heading; orgs beyond page 1 are invisible (old app paginates 50/page with load-more).
6. **`src/app/menu.tsx:82-101` — logout races and is incomplete.** `queryClient.clear()` runs before `authRn.signOut()` (which is not awaited); in-flight requests can repopulate the cache with the previous tenant's data. No navigation reset, and no FCM-token deletion (the old app's `auth-utils.ts:59`).
7. **`src/config/auth/rest-auth.ts:195-201` — a transient network failure at launch deletes the refresh token.** `restoreSession`'s `catch` cannot distinguish "refresh token revoked" from "no connectivity/DNS", so a flaky cold start signs the customer out permanently. Same pattern at `:240` (`setSession(null)` on any refresh failure).
8. **`src/config/auth/rest-auth.ts:110-113` — fire-and-forget keychain writes.** `void SecureStore.setItemAsync(...)`; a keychain failure is silent and shows up as an unexplained forced re-login next launch.
9. **`src/components/auth/auth-flow.tsx:285-292` — wrong error copy for non-credential failures.** `USER_DISABLED`, `TOO_MANY_ATTEMPTS_TRY_LATER` and a missing `EXPO_PUBLIC_FIREBASE_API_KEY` (thrown by `rest-auth.ts:74 requireApiKey`) all render "Could not sign in. Check the connection and try again."
10. **`src/components/auth/auth-flow.tsx:293` — `busy` is only cleared on the error path.** If sign-in resolves but `SessionGate` does not flip (e.g. the email claim problem in #2), the button is stuck on "Signing In" with no recovery.
11. **`src/components/auth/auth-flow.tsx:115` — `KeyboardAvoidingView behavior` is `undefined` on Android.** Auth inputs can sit under the Android keyboard; §4 says Android is first-class.
12. **`src/components/auth/auth-flow.tsx:193` — hardcoded `'#4285F4'` and a text "G" instead of the Google mark.** Colour literal in a repo whose `src/__tests__/no-color-literals.test.ts` forbids them (presumably on the exception list), and it violates Google's branding guidelines if it ever ships.
13. **`src/components/auth/auth-flow.tsx:407-408` — a network failure on "Send Password Reset" is rendered as a field validation error** under the email input, using the same slot as "Please enter a valid email".
14. **`src/app/_layout.tsx:19,69` — unhandled promise rejections.** `SplashScreen.preventAutoHideAsync()` and `SplashScreen.hideAsync()` are called without `.catch()`.
15. **`src/app/_layout.tsx:80` — `AuthFlow` and `LockScreen` render outside `ToastHost`/`SheetBackdropHost`.** Anything on the signed-out side that wants a toast cannot have one; that is why the sign-in error is inline text while the rest of the app toasts.
16. **`src/app/_layout.tsx:53-60` — `locked` is never reset on sign-out.** Harmless today only because `status !== 'signed-in'` short-circuits first; a future reordering re-locks a fresh sign-in.
17. **`src/app/(tabs)/more.tsx:81-94` — "Give Feedback" is a dead control.** It renders as a `Pressable` with `accessibilityRole="button"` and no `onPress`, while the file's own doc comment (lines 102-108) states unwired rows must render as plain dimmed text. `MoreRow` follows the rule; the feedback button does not.
18. **`src/app/menu.tsx:303` — `backgroundColor: '#000000'` hex literal**, same colour-literal rule as #12.
19. **`app.json` — `"orientation": "default"`** (old app locks portrait on phones), **no `updates`/`runtimeVersion`** (no OTA, no way to hotfix), and splash `backgroundColor: "#208AEF"` with `splash-icon.png` — the unmodified Expo template, not Horcery brand.
20. **`src/config/env/index.ts:96,102-116` — dead configuration.** `SENTRY_DSN` and the six `POSTHOG_*` values are parsed and exported but referenced by nothing in `src/`; a reader will reasonably assume crash reporting and analytics are wired.
21. **`src/services/api/user-management/{account-deletion-request,resend-verify-email}.ts` — services with no callers.** The delete-account and resend-verification capabilities exist at the service layer but have no UI, so "the API is there" can be mistaken for "the feature is there".

### C. Highest-risk items for a ship decision

Push notifications, forced-update wall, account deletion, Terms/Privacy links, create-organization/no-org dead-end, and crash reporting/analytics are all absent and all are either store-submission or reliability blockers — none of them appear in §2 or §6 as intentional removals or in `docs/scope/*` as scoped work.
